# AGENTS.md

ScholarPro is a scholarship management system: two independent apps. **No root `package.json`, no npm workspace, no docker-compose** — install and run everything from inside `backend/` or `frontend/`. (A root `package-lock.json` exists with no matching `package.json`; it's an orphan, ignore it.)

`backend/README.md` is the authoritative architecture doc — request flow (routes → controllers → services → Drizzle schema) and the AWS SES email queue design. Its env list is partly stale: the code reads `DB_*` creds and RSA key **files**, not `DATABASE_URL` / `JWT_*_SECRET`.

## Backend (`backend/`, Express 4 + TypeScript, Drizzle + postgres-js)

Layout: `controllers/` (69 `.ts`), `services/` (74), `routes/` (20), `db/` (32, incl. `db/schema/`), `utils/` (21), `validation/` (11), `middleware/` (8), `cron-jobs/` (4), `tests/` (19), `scripts/`, plus `bin/`, `docs/`, `type/`, `drizzle/`, `keys/`, `logs/`.

- **Run:** `npm run dev` (`cross-env NODE_ENV=dev ts-node-dev --respawn -r tsconfig-paths/register index.ts`) → port `3000` (override with `PORT`), API at `/api/v1`. Also `npm run stg` (`NODE_ENV=stg`).
- **`npm run pro` is broken** — it runs `node -r tsconfig-paths/register index.js` from the backend root, but only `index.ts` exists there. The real prod entry is `node dist/index.js` (what the Docker image runs). Use that.
- **Tests:** `npm test` = `cross-env NODE_OPTIONS=--max-old-space-size=8192 jest --detectOpenHandles`. 19 suites under `backend/tests/**` covering auth, application, dashboard, exam-session, interview, validation, plus one controller and one middleware suite. Coverage collected from `services/`, `controllers/`, `routes/`. Single file: `npx jest tests/services/auth/login.service.test.ts`.
- **Lint:** `npx eslint .` (flat config `eslint.config.mts`). It sets `parserOptions.project` but extends `tseslint.configs.recommended`, **not** `recommendedTypeChecked` — so it is not actually running type-aware rules. `no-explicit-any` is off, `no-unused-vars` is a warning.
- **Build:** `npm run build` = `tsc && npm run sentry:sourcemaps && tsc-alias`. `outDir: ./dist` with `rootDir: "."`. The Sentry step runs **unconditionally** and fails without `SENTRY_AUTH_TOKEN`; `backend/Dockerfile` guards it behind a build secret, the bare npm script does not. For local type-checking only, use `npx tsc --noEmit`.
- **DB:** `npm run db:generate` / `db:migrate` / `db:seed` (`tsx scripts/seed/generate-mock-data.ts`). Migrations in `backend/drizzle/` are generated and committed. The seed script **is** tracked in git and **is not** gitignored.
- **Env loading:** `dotenv.config({ path: ['.env.' + (NODE_ENV || 'dev'), '.env'] })` in `index.ts`. `db/index.ts` does the same load itself, but only `if (!process.env.DB_HOST)`. `.env*` is gitignored — so `.env.dev` / `.env.stg` are untracked, and so is `backend/.env.example` (it exists locally, matched by the `.env*` rule, but a fresh clone will not have it).
- **Env vars actually read in code:** `NODE_ENV`, `PORT`, `BASE_URL`, `CLIENT_URL`, `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`, `DB_DATABASE`, `JWT_PRIVATE_KEY_PATH`, `JWT_PUBLIC_KEY_PATH`, `SENTRY_DSN`, `UPLOAD_DIR`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `AWS_SES_FROM_EMAIL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `TELEGRAM_BOT_TOKEN`, `BAKONG_API_URL`, `BAKONG_API_TOKEN`, `BAKONG_MERCHANT_ID`, `BAKONG_MERCHANT_NAME`, `BAKONG_MERCHANT_CITY`, `BAKONG_REGISTERED_EMAIL`, `BAKONG_ACQUIRING_BANK`, `PUBLIC_REGISTER_URL`, `PUBLIC_FORGOT_PASSWORD_URL`, `MOBILE_FORGOT_PASSWORD_URL`. There is **no `DATABASE_URL`**. `DB_NAME` is authoritative for the runtime pool; `DB_DATABASE` appears only as a fallback in `drizzle.config.ts`.
- **Imports:** always use the tsconfig path aliases — `@routes/*`, `@utils/*`, `@db`, `@db/*`, `@controllers/*`, `@services/*`, `@middleware/*`, `@dtos/*`, `@validation/*`. Runtime works via `tsconfig-paths/register`; Jest resolves them via `moduleNameMapper`.
  - **Gotcha:** `jest.config.js` has no mapper for `@dtos/*`, so a test importing it fails to resolve. Add a mapper if you need one. `uuid` is also mapped to `tests/mocks/uuid.mock.ts` because v13 is ESM-only and Jest runs CommonJS.
- **Auth:** JWTs are RS256, signed/verified from RSA PEM files on disk at `JWT_PRIVATE_KEY_PATH` / `JWT_PUBLIC_KEY_PATH` (untracked `backend/keys/`). No HMAC secret. The frontend must be given the matching public key.
- **Style:** controllers and services intentionally mix class-based and functional styles (the backend README calls this out). Mirror whichever file you're editing.
- **Cron jobs auto-start on boot** — `index.ts` imports `cron-jobs/scheduler.ts`: exam-session status every 10 min, email queue every minute, `token-renewer` on import side effect, **plus one `processEmailQueue()` run immediately at startup**. The email queue writes to AWS SES, so a boot with live SES creds sends queued mail.
- **Rate limits:** global 1200 req / 5 min; `/api/v1/auth` is 20 / 15 min in production but **100 / 15 min in every other env**. `app.set("trust proxy", 1)`.
- **Dev-only routes:** `/login-demo` and `/debug-sentry` (throws) are registered when `NODE_ENV !== "production"`.
- **Logger quirks:** `utils/logger.ts` sets `const isProd = process.env.NODE_ENV === "dev"` (inverted) and passes `silent: isProd` to the Console transport — so `npm run dev` prints **no** console logs, only files. Separately, `systemLogger` is created at level `"error"`, so the `systemLogger.info(...)` calls in `index.ts` ("Server booting...", etc.) are silently dropped. `morgan("dev")` is registered unconditionally and does still print.
- **DB connect uses `ssl: false`** in both the pool and the `main()` self-test in `db/index.ts` (the `rejectUnauthorized: false` variant is commented out). Expect trouble against a managed PG that requires TLS.

## Frontend (`frontend/`, Next.js 16 App Router, React 19, Tailwind v4)

`app/` route groups: `(auth)/` (`login`, `committee-login`, `forgot-password`, `set-forgot-password`, `reset-password`), `(dashboard)/` (`dashboard`, `applicant`, `batch`, `communications`, `interview`, `schedule`, `score`, `setting`, `user-management`), `students/` (`login`, `signup`, `auth`, `application`, `exam`, `grade`, `profile`, `progress`), and `app/api/auth`.

- **Package manager is npm** for CI, Docker, and `packageManager: npm@10`. `frontend/pnpm-lock.yaml` is still committed — and `.husky/pre-commit` still runs `pnpm exec lint-staged`. So pnpm is not entirely vestigial, but don't add pnpm to anything new and don't regenerate `pnpm-lock.yaml`.
- **Run:** `npm run dev` = `cross-env NODE_TLS_REJECT_UNAUTHORIZED=0 next dev --turbopack -p 3001` → **port 3001**.
- **Start:** `npm run start` = `next start -p 3001` → also **3001**, not 3000. (See the port mismatch under CI/deploy.)
- **Build:** `npm run build` = `next build --turbopack`. No `output: "standalone"`.
- **Lint:** `npm run lint` = bare `eslint` (flat config `eslint.config.mjs`). Note the `plugin:@next/next/core-web-vitals` extend line is **commented out**, so only `typescript-eslint` recommended rules run — Next-specific rules are effectively off. Prettier is a devDep and wired through `lint-staged` (on `*.{js,jsx,ts,tsx}`), not through eslint. **No test suite** — no jest/vitest/playwright anywhere.
- **Next 16 middleware lives in root `proxy.ts`** (Next 16 renamed `middleware.ts` → `proxy.ts`). Two jobs: redirect to `/login` when the `refreshToken` cookie is absent and the path isn't public, and inject a per-request CSP nonce via the `x-nonce` request header. The gate is **cookie presence only** — no signature check. CSP `connect-src` is hardcoded to `'self' https://projectesting.site https://app.projectesting.site`; `script-src` adds `'unsafe-eval'` outside production. Matcher: `["/((?!api|_next/static|_next/image|favicon.ico|images|assets).*)"]`.
- **API wiring:** `api/api.ts` creates the axios client with `baseURL: "/api"`, `timeout: 60000`, `withCredentials: true`. `next.config.ts` rewrites `/api/:path*` → `${NEXT_PUBLIC_BACKEND_URL || "http://localhost:3000/api/v1"}/:path*`, with a special case listed *first*: `/api/v1/auth/google/callback` → `/students/auth/google/callback`.
- **Token model:** the access token lives in a **zustand store** (`lib/stores/auth-store`), not a cookie; only `refreshToken` is an HttpOnly cookie. The request interceptor lazily refreshes when memory has no token; the response interceptor refreshes once on 401 using an `isRefreshing` flag + `refreshQueue` and an `_retry` guard (429 short-circuits before any of this). `fetchValidatedData` / `postValidatedData` / `putValidatedData` wrap calls in Zod response parsing.
- **Client-side JWT verification:** `lib/utils/jwt-verify.ts` uses `jose` — `importSPKI(..., "RS256")` then `jwtVerify` with `algorithms: ["RS256"]` and `clockTolerance: 30`, requiring `id` and `role` and validating `role ∈ {admin, committee, student}`. It reads `NEXT_PUBLIC_JWT_PUBLIC_KEY` and normalizes literal `\n` and single-line PEMs. A missing or malformed key makes the internal `getPublicKey()` throw, but that's caught and returned as `{ valid: false, error }` — it does **not** propagate to the caller, so an unset key degrades to "every token is invalid" rather than a hard crash. Note the payload cast types `role` as `"admin" | "committee"` while the interface and the runtime check both include `"student"`.
- **Duplicate utils:** `lib/utils/` has `helper.ts` **and** `help.ts`, and `sanitize.ts` **and** `sanitizer.ts` (also `department-mapper.ts`, `email-variables.ts`, `student-portal.ts`, `jwt-verify.ts`). Grep before adding another.
- `next.config.ts` also sets `compiler.removeConsole` in production, `productionBrowserSourceMaps: false`, `turbopack.root: __dirname`, and wraps everything in `withSentryConfig` (org `capstone-project-pg`, project `javascript-nextjs`, `tunnelRoute: "/monitoring"` to dodge ad-blockers).

## CI / deploy

- **`.github/workflows/ci-cd.yml`** is the only workflow. Triggers: push and PR to `main` and `dev`; `concurrency` group `scholarpro-<ref>` with `cancel-in-progress: true`; Node **20**; `npm ci` in each app.
  - `backend-tests` (always): `npx eslint .` then `npm test -- --runInBand --passWithNoTests`. **No backend build step.**
  - `frontend-quality` (always): `npm run lint` then `npm run build`.
  - `docker-build` (push only, needs both above): buildx matrix over `backend` and `frontend`, pushes to `ghcr.io/<lowercased owner>/scholarpro-<app>` tagged with both `github.sha` and a sanitized lowercase branch tag. Passes `SENTRY_AUTH_TOKEN` as a **build secret**. It passes **no `build-args`**.
  - `deploy` (push to `main`/`dev` only): SSHes `scripts/deploy.sh` using `DEPLOY_HOST` / `DEPLOY_USER` / `DEPLOY_PORT` and exits 0 with a message if host or user is unset.
- **`scripts/deploy.sh`**: `set -euo pipefail`; requires `GITHUB_TOKEN` (exits 1 without it); pulls both images by `IMAGE_TAG`; creates the `scholarpro` network if missing; `docker rm -f` then re-runs `scholarpro-backend` (`-p 3000:3000`) and `scholarpro-frontend` (`-p 3001:3000`).
- **Branch → environment:** `main` → `production`, `dev` → `staging`, via a GitHub `environment` expression.
- `infrastructure/terraform/` (`main.tf`, `variables.tf`) is an alternative GCP Cloud Run path, **not referenced by CI**. `monitoring/promtail-config.yaml` configures Loki scraping and is likewise not wired into CI or `deploy.sh`. The two `*.patch` files at repo root are historical security-fix artifacts — leave them alone.

## Known gaps — verified, worth knowing before you trust a deploy

1. **Deploy injects no configuration.** `deploy.sh` passes only `-e NODE_ENV` to both containers. There is no `--env-file` and no `-e DB_*` / `JWT_*_PATH` / `AWS_*`. As written, the deployed backend has no database credentials and no JWT key paths, and the frontend has no `NEXT_PUBLIC_*`. A working deploy needs env injection added here.
2. **Frontend port mismatch in the image.** `frontend/Dockerfile` declares `EXPOSE 3000` and `CMD ["npm", "start"]`, but `start` is `next start -p 3001`, so the server binds **3001** inside the container while `deploy.sh` maps host `3001` → container **3000**. The published frontend is unreachable as configured.
3. **`NEXT_PUBLIC_*` build args are never supplied.** `frontend/Dockerfile` declares `ARG NEXT_PUBLIC_BACKEND_URL` / `NEXT_PUBLIC_JWT_PUBLIC_KEY`, but the CI build step passes only `secrets`, no `build-args`. Images built by CI therefore bake in empty values: rewrites fall back to `http://localhost:3000/api/v1` and client-side JWT verification always fails.
4. **`npm run pro` cannot work** (see Backend). The Docker path is the only working prod entry.
5. **`/reset-password` is a public route that isn't public.** `app/(auth)/reset-password/` exists and `api/api.ts`'s `redirectToLogin()` lists `/reset-password` as public, but `proxy.ts`'s `publicPaths` omits it (it lists `set-forgot-password` instead). An unauthenticated visit to `/reset-password` bounces to `/login`. Also note `proxy.ts`'s `publicPaths` uses `startsWith`, so `/login` also matches `/login-anything`.
6. **The frontend dev script disables TLS verification** process-wide via `NODE_TLS_REJECT_UNAUTHORIZED=0`; that env var leaks into anything the dev server spawns.
